# 材质通道语义调查（WuWa，帧 3422）

状态：**调查完成，结论是"不能按标准 PBR 语义直接接"**。本文记录证据，避免下一轮重复走这条路。

## 问题

`build.py` 的 `classify_textures` 只挑出底色（SRGB 视图）和法线（BC5/BC7），其余贴图全部丢弃。
一个自然的假设是：剩下那些线性（非 SRGB）的 BC1/BC7 贴图里应该有 ORM（AO/粗糙度/金属度），接上就能显著改善画面。

## 数据规模

617 个不透明 draw 中，503 个在底色之外还绑定了至少一张线性贴图。数量上确实"有东西可接"。

## 证据（为什么这个假设不成立）

用 `rf_extract.py` 新增的 `shaders` 模式导出了 5 个代表 draw 的像素着色器反汇编
（`workspace/wuwa_bridge/shaders/shaders.json`）。逐条读 G-Buffer 写出的指令：

- **eid 2037（天空穹顶）**
  - `o0.xyz = -r0.xyz`：底色。
  - `o1`：法线（`r3.xy * 0.5 + 0.5`，标准编码）。
  - `o3.xyz = lerp(r7.yzw, 1.0, saturate(cb0[279].w))`，其中 `r7` 来自 `t2` 采样：
    这是**三通道反射/高光色调**被一个标量参数混向白色，不是 ORM。
  - `o2.y = min(mask, ...)`，`mask` 由 `t0`（slot 0，恒定 `R32_FLOAT`）采样乘 10 后与 cbuffer 常量比较、取 min 得到：
    这是**逐像素遮罩/阈值**，不是粗糙度。
  - 着色器中没有 `roughness` / `metallic` / `specular` 之类的命名参数；PBR 输入来自 cbuffer 常量与多层 LUT（`t5`/`t6` 是 3D LUT 采样，eid 2037 有 11 处）。

- **eid 4888（室内木质房间）**：7 个渲染目标（`o0`..`o6`），`o3.xyz` 同样来自 `lerp(r5, 1.0, w)` 形式的三通道值；
  `cb2[5..51]` 的行是 `[0.62, 3.0, 0.66, 1.9]`、`[0.9, 0, 0.1125, 0]` 这类**逐材质标量组**，不是通道打包纹理。

- **贴图槽位不稳定**：slot 0–15 的角色在样本间变化（slot 1 有 10 次是法线、6 次是底色、6 次是其他），
  所以也不能用"某个槽位固定是 ORM"来识别。

- **共享常量块不是材质块**：被 392 个 draw 共享的 `ps2` 块（`38dc247ab23ce83e`）是**全局光照参数**；
  真正的逐材质常量在 `ps3`（213 个不同 hash，多数只被 1–32 个 draw 用），行内容形如上面的标量组。

## 结论

1. WuWa 的 GBuffer 不是"底色 + 法线 + ORM"的三件套，而是更多通道（最多 7 个 RT）加 LUT 驱动的着色。
2. 把任意一张线性伴随贴图当粗糙度接进 UE，等于凭空发明材质响应，会把画面改坏而不是改好。
3. 要真正提升材质保真度，正确路径是**逐 draw 解码材质常量块**（`ps3` 那类）并把它们映射到 UE 的参数，
   而不是从贴图猜语义。这是一项独立的、有成体系的工作，不能靠一轮调查完成。
